WHAT IS THE CAPSTONE?
  A single, complete, real-world AI assistant that demonstrates
  everything from Phase 3. This is what you show to clients or
  employers. It's your proof of skill.

CAPSTONE REQUIREMENTS:
  [ ] Solves a real business problem (not a toy example)
  [ ] System prompt defines a clear, specific role
  [ ] All API calls logged with cost via tracker.py
  [ ] At least 2 tools with proper error handling
  [ ] Returns structured output (validated JSON) somewhere
  [ ] Test suite: 10+ assertions pass in one command
  [ ] Budget cap active
  [ ] Human approval for at least one risky action
  [ ] README.md explains what it does and how to run it

CAPSTONE IDEAS (pick one):

  IDEA 1 — INVOICE PROCESSOR:
    Input: raw invoice text (email or paste)
    Tools: extract_invoice_data, lookup_vendor, flag_duplicate
    Output: structured JSON + approval to log it
    Business value: replaces manual data entry for accounting

  IDEA 2 — SUPPORT TICKET ROUTER:
    Input: customer message
    Tools: classify_issue, lookup_customer, draft_response
    Output: category + drafted reply (with approval to send)
    Business value: faster support, consistent responses

  IDEA 3 — PRODUCT RESEARCH ASSISTANT:
    Input: product name or category
    Tools: search_products, get_pricing, compare_features
    Output: structured comparison + recommendation
    Business value: helps sales teams answer customer questions

  IDEA 4 — MEETING NOTES PROCESSOR:
    Input: raw meeting notes text
    Tools: extract_action_items, assign_owners, set_deadlines
    Output: structured action list + draft follow-up email
    Business value: saves 30 min per meeting for every team

HOW TO PICK:
  Pick the one closest to a real problem you've seen.
  "I built this because X company had this problem" is more
  convincing to a client than "I built this as an exercise."

CAPSTONE SELF-ASSESSMENT RUBRIC
----------------------------------------------------------------

Score yourself 1–5 on each dimension after you finish.
Be honest. This is for you, not for anyone else.

  BUSINESS VALUE (1–5):
    1 = toy example with no real use case
    3 = solves a real problem but narrowly
    5 = a client would pay for this today

  TOOL DESIGN (1–5):
    1 = tools are vague, model picks wrong ones
    3 = tools work but descriptions could be clearer
    5 = descriptions are specific, model always picks correctly

  ERROR HANDLING (1–5):
    1 = crashes on bad input
    3 = handles errors but doesn't recover gracefully
    5 = all 3 error types handled, model self-corrects

  TEST COVERAGE (1–5):
    1 = fewer than 5 tests
    3 = 10 tests, most pass
    5 = 10+ tests all pass, evals reviewed weekly
        (for a 5: also open evals.json and record last_reviewed
        + last_result for each entry — not just run_tests.py)

  README QUALITY (1–5):
    1 = no README
    3 = README exists but incomplete
    5 = a stranger could set it up and run it in 5 minutes

  TARGET: 3+ on all dimensions before calling Phase 3 done.
  If any dimension is below 3, fix it before moving on.

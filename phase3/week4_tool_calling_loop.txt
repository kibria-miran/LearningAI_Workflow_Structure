DAY 1: ONE TOOL — CONFIRM MODEL RETURNS A TOOL CALL
Estimated: 60 min | Cost: <$0.005
----------------------------------------------------------------

CONCEPT:
  Tool calling lets the model request that YOUR code runs a
  function and returns the result.

  The model doesn't run code. It can't. What it does is say:
  "I need the result of function X with these arguments."
  Your code runs the function and sends the result back.

THE FLOW (memorize this):
  1. You send messages + tool definitions to the model
  2. Model decides it needs a tool -> finish_reason = "tool_calls"
  3. Your code reads the tool name and arguments
  4. Your code executes the function
  5. Your code sends the result back to the model
  6. Model uses the result to form a final answer

ANALOGY:
  The model is a manager who can't leave their desk.
  Tools are employees who can go do things.
  Manager: "Go check the warehouse for item #4521."
  Employee (your code): checks, comes back with the answer.
  Manager: uses that answer to respond to the customer.

HOW YOU DEFINE A TOOL:
  A JSON schema with: name, description (when to use it),
  and parameters (what arguments it takes).
  The model reads the description to decide when to call it.
  Vague description = wrong tool selected. Be specific.

CODE:
  # day1_one_tool.py
  from dotenv import load_dotenv
  import os, json
  from tracker import tracked_call

  load_dotenv()

  tools = [{
      "type": "function",
      "function": {
          "name": "get_order_status",
          "description": "Look up the current status of a customer order by order ID. Use this when the user asks about an order, shipment, or delivery.",
          "parameters": {
              "type": "object",
              "properties": {
                  "order_id": {"type": "string", "description": "The order ID, e.g. '4521'"}
              },
              "required": ["order_id"]
          }
      }
  }]

  messages = [{"role": "user", "content": "What's the status of order 4521?"}]

  result = tracked_call(messages, tools=tools)

  print("finish_reason:", result["finish_reason"])
  print("cost:         ", result["cost"])

  if result["finish_reason"] == "tool_calls":
      # tool_calls is a list; each item has .function.name and .function.arguments
      # It is None when finish_reason is "stop" — always check finish_reason first
      tc = result["tool_calls"][0]
      print("Model wants to call:", tc.function.name)
      print("With arguments:     ", tc.function.arguments)
  else:
      print("Model answered directly:", result["content"])

DAY 2: EXECUTE THE TOOL, RETURN RESULT, GET FINAL ANSWER
Estimated: 60–90 min | Cost: <$0.01
----------------------------------------------------------------

CONCEPT:
  After the model requests a tool call, you run the function
  and send the result back in a message with role="tool".
  The model then uses that result to write its final answer.

  IMPORTANT — appending the assistant message:
  tracked_call() returns "message" as a ChatCompletionMessage object.
  Use message.model_dump() to convert it to a dict before appending.
  This works with both the SDK and raw HTTP requests.
  Guard against None: only call model_dump() if message is not None.
  Verify by printing the dict on your first run — confirm tool_calls
  is serialized as a list of dicts inside it.

THE TOOL RESULT MESSAGE:
  {
    "role": "tool",
    "tool_call_id": "the id from the model's tool_calls",
    "content": "the result of your function as a string (JSON)"
  }
  The tool_call_id links the result to the specific request.

CODE:
  # day2_execute_tool.py
  from dotenv import load_dotenv
  import os, json
  from tracker import tracked_call

  load_dotenv()

  ORDERS = {
      "4521": {"status": "shipped", "eta": "Dec 10", "item": "Blue Hoodie"},
      "9988": {"status": "processing", "eta": "Dec 15", "item": "Red Mug"},
      "1234": {"status": "delivered", "eta": None, "item": "Wireless Keyboard"}
  }

  def get_order_status(order_id: str) -> str:
      order = ORDERS.get(order_id)
      if not order:
          return json.dumps({"error": f"Order {order_id} not found"})
      return json.dumps(order)

  tools = [{
      "type": "function",
      "function": {
          "name": "get_order_status",
          "description": "Look up the current status of a customer order by order ID.",
          "parameters": {
              "type": "object",
              "properties": {"order_id": {"type": "string"}},
              "required": ["order_id"]
          }
      }
  }]

  messages = [{"role": "user", "content": "What's the status of order 4521?"}]

  # Step 1: Get tool call request
  result = tracked_call(messages, tools=tools)
  print(f"Step 1 cost: ${result['cost']:.6f}")

  if result["finish_reason"] == "tool_calls":
      tc = result["tool_calls"][0]
      args = json.loads(tc.function.arguments)

      # Step 2: Execute the function
      tool_result = get_order_status(args["order_id"])
      print("Tool result:", tool_result)

      # Step 3: Add model's message + tool result to messages
      # Guard against None before calling model_dump()
      if result["message"] is not None:
          messages.append(result["message"].model_dump())
      messages.append({
          "role": "tool",
          "tool_call_id": tc.id,
          "content": tool_result
      })

      # Step 4: Get final answer
      final = tracked_call(messages, tools=tools)
      print(f"Step 2 cost: ${final['cost']:.6f}")
      print("\nFinal answer:", final["content"])

DAY 3: BUILD THE LOOP
Estimated: 90 min | Cost: <$0.02
----------------------------------------------------------------

CONCEPT:
  Some tasks require multiple tool calls in sequence.
  You need a loop that keeps going until:
  - finish_reason is "stop" (model is done), OR
  - You've hit the iteration cap (safety limit), OR
  - finish_reason is "length" or "content_filter" (errors)

  The cap is critical. Without it, a confused model could loop
  forever, calling tools repeatedly and draining your budget.

ANALOGY:
  The loop is like a project manager delegating tasks.
  Manager assigns task -> employee does it -> reports back ->
  manager assigns next task -> repeat until done.
  The cap is the deadline: after 5 rounds, we stop regardless.

CODE:
  # day3_loop.py
  from dotenv import load_dotenv
  import os, json
  from tracker import tracked_call

  load_dotenv()

  ORDERS = {
      "4521": {"status": "shipped", "eta": "Dec 10", "item": "Blue Hoodie", "customer": "John"}
  }

  def get_order_status(order_id: str) -> str:
      order = ORDERS.get(order_id)
      return json.dumps(order if order else {"error": f"Order {order_id} not found"})

  def draft_email(customer_name: str, message: str) -> str:
      return json.dumps({
          "draft": f"Dear {customer_name},\n\n{message}\n\nBest regards,\nSupport Team"
      })

  TOOL_MAP = {
      "get_order_status": get_order_status,
      "draft_email": draft_email
  }

  tools = [
      {
          "type": "function",
          "function": {
              "name": "get_order_status",
              "description": "Look up the current status of a customer order by order ID. Use when asked about orders, shipments, or deliveries.",
              "parameters": {
                  "type": "object",
                  "properties": {"order_id": {"type": "string"}},
                  "required": ["order_id"]
              }
          }
      },
      {
          "type": "function",
          "function": {
              "name": "draft_email",
              "description": "Draft a reply email to a customer. Use after you have the information needed to respond.",
              "parameters": {
                  "type": "object",
                  "properties": {
                      "customer_name": {"type": "string"},
                      "message": {"type": "string", "description": "The email body content"}
                  },
                  "required": ["customer_name", "message"]
              }
          }
      }
  ]

  def run_agent(user_message: str, max_iterations: int = 5) -> str:
      """
      Run the agent loop until done or max_iterations reached.
      Every iteration is logged via tracked_call.
      """
      messages = [
          {"role": "system", "content": "You are a support assistant. Use tools to look up orders and draft replies."},
          {"role": "user", "content": user_message}
      ]
      total_cost = 0.0

      for iteration in range(max_iterations):
          print(f"\n--- Iteration {iteration + 1} ---")
          result = tracked_call(messages, tools=tools)
          total_cost += result["cost"]
          print(f"finish_reason: {result['finish_reason']} | cost: ${result['cost']:.6f}")

          if result["finish_reason"] == "stop":
              print(f"Total cost: ${total_cost:.6f}")
              return result["content"]

          if result["finish_reason"] == "length":
              return "ERROR: Response truncated mid-loop. Increase max_tokens."

          if result["finish_reason"] == "content_filter":
              return "ERROR: Content filtered mid-loop. Review your prompts."

          if result["finish_reason"] == "tool_calls":
              # tool_calls is guaranteed non-None here because finish_reason is "tool_calls"
              if result["message"] is not None:
                  messages.append(result["message"].model_dump())
              for tc in result["tool_calls"]:
                  fn_name = tc.function.name
                  fn_args = json.loads(tc.function.arguments)
                  print(f"Calling: {fn_name}({fn_args})")

                  tool_result = TOOL_MAP[fn_name](**fn_args)
                  print(f"Result:  {tool_result}")

                  messages.append({
                      "role": "tool",
                      "tool_call_id": tc.id,
                      "content": tool_result
                  })

      return f"ERROR: Max iterations ({max_iterations}) reached without final answer."

  answer = run_agent("Look up order 4521 and draft a reply to the customer about their shipment status.")
  print("\n=== FINAL ANSWER ===")
  print(answer)

DAY 5: ERROR HANDLING — BAD ARGS, UNKNOWN TOOL, TOOL CRASH
Estimated: 60–90 min | Cost: <$0.01
----------------------------------------------------------------

CONCEPT:
  Tools fail. The model sometimes passes wrong argument types,
  calls a tool that doesn't exist, or your function throws an
  exception. Handle all 3 without crashing.

  Professional approach: catch the error, send it back to the
  model as a tool result. The model often self-corrects.

THE 3 ERROR TYPES:

  ERROR 1 — BAD ARGS:
    Model passes {"order_id": 4521} (integer) but function expects string.
    FIX: Wrap function execution in try/except TypeError.

  ERROR 2 — UNKNOWN TOOL:
    Model hallucinates a tool name not in TOOL_MAP.
    FIX: Check if fn_name is in TOOL_MAP before calling.

  ERROR 3 — TOOL CRASH:
    Your function raises an exception (DB down, API timeout).
    FIX: Wrap in try/except, return {"error": str(e)} as JSON.

CODE:
  # day5_error_handling.py

  def safe_execute(fn_name: str, fn_args: dict) -> str:
      """
      Safely execute a tool. Always returns a JSON string. Never raises.
      """
      if fn_name not in TOOL_MAP:
          return json.dumps({"error": f"Unknown tool: '{fn_name}'. Available: {list(TOOL_MAP.keys())}"})
      try:
          return TOOL_MAP[fn_name](**fn_args)
      except TypeError as e:
          return json.dumps({"error": f"Bad arguments for '{fn_name}': {e}"})
      except Exception as e:
          return json.dumps({"error": f"Tool '{fn_name}' crashed: {e}"})

  # Test all 3 error types explicitly:

  # ERROR 1 — bad args
  print(safe_execute("get_order_status", {"wrong_key": "123"}))

  # ERROR 2 — unknown tool
  print(safe_execute("nonexistent_tool", {}))

  # ERROR 3 — tool crash (use this broken tool for testing)
  def _broken_tool_for_testing() -> str:
      raise RuntimeError("Simulated DB outage")

  TOOL_MAP["_broken_tool_for_testing"] = _broken_tool_for_testing
  print(safe_execute("_broken_tool_for_testing", {}))

  # Always remove test tools after testing — otherwise the model
  # may try to call them on subsequent runs.
  del TOOL_MAP["_broken_tool_for_testing"]

DAY 6: HUMAN APPROVAL FOR RISKY TOOLS
Estimated: 60 min | Cost: <$0.01
----------------------------------------------------------------

CONCEPT:
  Some tools have real-world consequences that can't be undone:
  sending an email, deleting a record, charging a customer.
  For these, pause the loop and ask the human: approve? (y/n)

  This is "human-in-the-loop" — a key safety feature in any
  production AI system.

ANALOGY:
  A junior employee who can research anything independently but
  needs manager approval before sending any external communication.

SAFE vs RISKY:
  SAFE (no approval): get_order_status, get_price, search_*
  RISKY (needs approval): send_email, delete_record, process_refund

CODE:
  # Add to run_agent():

  RISKY_TOOLS = {"send_email", "delete_record", "process_refund"}

  def _get_approval(fn_name: str, fn_args: dict) -> bool:
      print(f"\n⚠️  APPROVAL NEEDED")
      print(f"Tool: {fn_name}")
      print(f"Args: {json.dumps(fn_args, indent=2)}")
      return input("Approve? (y/n): ").strip().lower() == "y"

  # Inside the tool_calls loop — collapsed to one messages.append:
  for tc in result["tool_calls"]:
      fn_name = tc.function.name
      fn_args = json.loads(tc.function.arguments)

      if fn_name in RISKY_TOOLS and not _get_approval(fn_name, fn_args):
          # Send rejection back to model so it knows the action was blocked.
          # The model will see this on the next iteration and respond accordingly.
          tool_result = json.dumps({"status": "rejected", "reason": "User did not approve."})
      else:
          tool_result = safe_execute(fn_name, fn_args)

      messages.append({"role": "tool", "tool_call_id": tc.id, "content": tool_result})

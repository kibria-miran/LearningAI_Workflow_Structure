INCREMENTAL RE-INDEXING
----------------------------------------------------------------

CONCEPT:
  Right now, build_index.py re-embeds ALL documents every time.
  If you add one new file, you re-embed 1000 chunks unnecessarily.

  INCREMENTAL APPROACH:
  1. Hash each file's content (MD5 or SHA256)
  2. Store hashes in a manifest file (phase4/results/manifest.json)
  3. On next run: only re-embed files whose hash changed
  4. Merge new embeddings with existing index

CODE:
  # In build_index.py — add incremental logic

  import hashlib, json, os

  MANIFEST_FILE = "phase4/results/manifest.json"

  def file_hash(path: str) -> str:
      with open(path, "rb") as f:
          return hashlib.md5(f.read()).hexdigest()

  def load_manifest() -> dict:
      if os.path.exists(MANIFEST_FILE):
          with open(MANIFEST_FILE) as f:
              return json.load(f)
      return {}

  def save_manifest(manifest: dict):
      with open(MANIFEST_FILE, "w") as f:
          json.dump(manifest, f, indent=2)

  # In build_index.py main():
  manifest = load_manifest()
  changed_files = []
  for fname in os.listdir(DATA_DIR):
      fpath = os.path.join(DATA_DIR, fname)
      current_hash = file_hash(fpath)
      if manifest.get(fname) != current_hash:
          changed_files.append(fname)
          manifest[fname] = current_hash

  print(f"Changed files: {len(changed_files)} | Unchanged: {len(manifest) - len(changed_files)}")
  # Only re-embed changed_files, then merge with existing index

VERIFY:
  Run build_index.py twice. Second run: "Changed files: 0".
  Add a new file to data/. Third run: "Changed files: 1".

RETRY + FALLBACK ON PROVIDER ERRORS
----------------------------------------------------------------

CONCEPT:
  In production, the LLM provider will occasionally fail.
  Your RAG system should handle this gracefully.

  RETRY: try the same call again after a short wait.
  FALLBACK: if retries fail, try a different model or provider.

  tracker.py already has retry for RateLimitError.
  Add fallback for other errors (timeout, server error).

CODE ADDITION to tracker.py:
  # Add fallback model
  FALLBACK_MODEL = "deepseek-chat"  # or a different provider

  def tracked_call_with_fallback(messages, model="deepseek-chat", **kwargs):
      """Try primary model, fall back on repeated failure."""
      try:
          return tracked_call(messages, model=model, **kwargs)
      except Exception as e:
          print(f"Primary model failed: {e}. Trying fallback...")
          return tracked_call(messages, model=FALLBACK_MODEL, **kwargs)

  should attempt the fallback model.

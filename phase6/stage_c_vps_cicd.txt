================================================================
PHASE 6 - STAGE C: VPS + CI/CD (do during Phase 5)
Estimated time : 6-8 hrs total
Estimated cost : ~$5-6/month VPS
================================================================

GOAL: Push to main -> tests pass -> app updates on the server over HTTPS.

----------------------------------------------------------------
CHECKPOINT 1: HARDEN A FRESH VPS
----------------------------------------------------------------
  Pick a small Ubuntu LTS VPS with 2 GB RAM or more (the embedding
  model needs memory).
    ssh-keygen -t ed25519            # on your laptop
    ssh-copy-id deploy@SERVER_IP     # after creating user 'deploy' with sudo
  On the server:
    sudo nano /etc/ssh/sshd_config   -> PasswordAuthentication no
                                        PermitRootLogin no
    sudo systemctl restart ssh
    sudo ufw default deny incoming && sudo ufw allow OpenSSH
    sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
  KEEP a second SSH session open while changing SSH settings.

----------------------------------------------------------------
CHECKPOINT 2: DEPLOY + HTTPS
----------------------------------------------------------------
  Install Docker, clone the repo, create .env ON THE SERVER only.
  Point a domain (A record) at the server. Caddy gives automatic HTTPS:
    Caddyfile:
      rag.example.com {
          reverse_proxy rag-app:8000
      }
  Run Caddy as another compose service on the same network and publish
  only 80/443. Keep 8000/5678 bound to 127.0.0.1.

----------------------------------------------------------------
CHECKPOINT 3: GITHUB ACTIONS
----------------------------------------------------------------
  .github/workflows/deploy.yml (adapt paths):

    name: ci-cd
    on: { push: { branches: [main] } }
    jobs:
      test:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-python@v5
            with: { python-version: "3.11" }
          - run: pip install -r phase6/requirements.txt pytest
          - run: python -m pytest phase4/tests -q       # only tests that need NO API key
      deploy:
        needs: test
        runs-on: ubuntu-latest
        steps:
          - uses: appleboy/ssh-action@v1
            with:
              host: ${{ secrets.SERVER_HOST }}
              username: deploy
              key: ${{ secrets.SERVER_SSH_KEY }}
              script: |
                cd ~/ai-roadmap && git pull
                cd phase6 && docker compose up -d --build

  Store SERVER_HOST and SERVER_SSH_KEY in repo Settings -> Secrets.
  The API key stays in the server .env, NEVER in GitHub or the image.
  Evals that call the real API: run them on a schedule or manually,
  with a spend limit, not on every push. Fail the pipeline if your
  offline prompt tests or recorded eval score drop below baseline.

VERIFY: break a test on purpose, push -> deploy must NOT run.
        docker history <image> | grep -i key   -> nothing.

COMMIT: git commit -m "stage C: vps + ci/cd"
EXIT WHEN:
  [ ] https://your-domain/health returns ok   [ ] password SSH disabled
  [ ] failing test blocks deploy              [ ] no secret in repo/image
